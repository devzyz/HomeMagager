# 数据库备份与恢复指南（本地开发版）

> 本文档覆盖**本地**备份的恢复流程。云端（阿里云盘）备份为未接入项，恢复流程将在接入后补充。
> ⚠️ 禁止在正常运行的服务内覆盖数据库。恢复前必须停止应用进程。

## 备份内容说明

- 备份文件：`data/backups/local/family-expense-YYYYMMDD-HHmmss-<id>.sqlite.gz`
- 校验元数据：同名 `.json` 文件（含 SHA-256、大小、应用版本、数据库迁移版本、快照时间）
- 备份中的 Session 已清空（恢复后所有用户需重新登录）
- 新备份包含同名 `.sqlite.gz.attachments/` 目录，保存该数据库快照引用的附件；JSON 清单记录每个附件的大小与 SHA-256。三个部分必须成组保存或传输。
- 旧版 `attachments_included: false` 备份仍支持恢复数据库，但附件需要旧的单独副本。
- gzip 不是加密。备份包含账单数据与密码哈希，请妥善保管备份文件

## 手动备份

页面：设置 → 备份 → 「立即本地备份」；或触发后查看历史记录。

自动备份：每小时检查一次，距最近成功备份满 7 天（`BACKUP_INTERVAL_DAYS`）时自动执行；失败后至少间隔 1 小时才会重试。

## 恢复流程

### 1. 停止应用

关闭正在运行的 dev 服务进程（Ctrl+C），确认没有其他进程占用数据库文件。

### 2. 执行恢复命令

```bash
pnpm --filter @hm/server run backup:restore -- <备份文件的绝对路径>.sqlite.gz
```

可选参数：

- `--meta <元数据.json>`：默认自动使用 `<归档>.json`，也可显式指定
- `--target <路径>`：默认使用 `DATABASE_PATH`（开发版默认 `data/database/family-expense.db`）
- `--uploads <路径>`：附件恢复目录，默认使用 `UPLOAD_DIR`。恢复到测试目录时同时指定 `--target` 和 `--uploads`；建议使用绝对路径，避免 pnpm 工作目录差异
- `--yes`：跳过交互确认（用于脚本）

命令会自动完成：数据库与附件 SHA-256 校验 → 解压 → 完整性/外键/版本兼容性检查 → 在临时库执行迁移 → 恢复附件 → 将当前数据库（`.db`/`-wal`/`-shm` 成组）保留为回滚副本 → 替换数据库。同名且内容不同的现有附件会导致恢复被拒绝；已有的其他附件保留，便于回滚。

### 3. 启动并核对

重新启动应用后核对：

1. 使用恢复出的账号登录（Session 全部失效，需重新登录）
2. 检查「费用」列表数量与「报表」汇总是否与备份前一致
3. 在「设置 → 成员」核对账号启停状态；如担心密码遗失，可由其他成员执行「重置密码」

### 4. 附件恢复（如需）

新备份由恢复命令自动校验并恢复附件；旧版仅数据库备份仍需将之前单独备份的附件复制回 `UPLOAD_DIR`。请打开费用详情验证图片及 PDF 能正常查看。

## 回滚

恢复命令执行前会自动把当前数据库保留为 `data/database/rollback-<时间戳>/` 目录。
如恢复后发现问题，停止应用，把该目录内的 `.db`（及 `-wal`、`-shm`，若存在）复制回 `data/database/` 即可。

## 常见问题

- **提示“备份来自更新的应用版本”**：备份所含迁移版本比当前应用新，说明不能把新备份恢复到旧程序上。请先升级应用再恢复。
- **提示“SHA-256 校验失败”**：归档与元数据不匹配（文件损坏或下载不完整），请更换其他备份文件。
- **恢复后部分附件缺失**：见上文「附件恢复」。
